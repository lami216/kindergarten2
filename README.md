# نظام إدارة الروضة

> **واجهة التشغيل الأصلية:** [ربط صفحات GitHub Pages نفسها بالحساب والبيانات الفعلية](docs/ORIGINAL_PAGES_LIVE.md). لا يُعاد رسم التصميم في Streamlit؛ أدوات الإدارة المفيدة متاحة داخل الواجهة نفسها. هذه الإضافة لا تعني أن الإصدار نُشر تلقائيًا.

> التشغيل في هذا الفرع: صفحات HTML/CSS/JS الأصلية مع خدمات Python/PostgreSQL، مع إدارة موحدة؛ Streamlit محفوظ لاختبارات التوافق (انظر live_pages.py وdb.py).
> إنشاء الطفل والأهل يتم الآن في صفحة الطلاب، وصفحة الأهل للبحث والعرض والتعديل.
> صفحة الأقسام تدير أسماء الأقسام ونقل الأطفال، والسجل القديم يبقى محفوظًا.


## 🗂️ هيكلة المشروع (وحدات مستقلة)
```
app.py              → نقطة التشغيل فقط (إعداد الصفحة + تسجيل الدخول + التوجيه بين الشاشات)
sidebar.py           → القائمة الجانبية (الشعار، الإحصائيات السريعة، أزرار التنقل)
auth.py               → شاشة تسجيل الدخول
ui.py                  → عناصر مشتركة (بطاقات، عناوين الأقسام، الشعار...)
receipt.py            → وصل الدفع القابل للطباعة بضغطة واحدة
style.py               → التنسيق العام (الألوان، الاستجابة للجوال)
db.py / helpers.py     → قاعدة البيانات والمنطق المشترك (لا تُعدَّل عادة)

sections/
    dashboard.py        → لوحة التحكم
    students.py          → الطلاب
    parents.py            → أولياء الأمور
    teachers.py            → المعلمون
    classes.py              → الصفوف
    academic_years.py        → السنوات الدراسية
    registration.py           → التسجيل
    payments.py                → الدفعات المالية
    reports.py                  → التقارير
```

## التشغيل والتحديث

يتطلب Python 3.12 وPostgreSQL. ثبّت `requirements.txt` كما هو، ثم ضع رابط PostgreSQL وحساب المسؤول في `.streamlit/secrets.toml` وفق إعدادات المصادقة. لا تُحفظ الأسرار في Git.

قبل تشغيل التطبيق لأول مرة **وعند كل تحديث**، نفّذ في خطوة النشر المستقلة:

```sh
python -m schema_migrations
python -m live_pages --config /etc/kindergarten2/secrets.toml --origin https://YOUR-DOMAIN --port 8522 --trusted-proxy 127.0.0.1
```

يمكن قراءة الرابط من متغير بيئة بدل ملف الأسرار: `python -m schema_migrations --dsn-env DATABASE_URL`.
الترحيل مرقّم ويُنفذ داخل معاملة واحدة بقفل يمنع تداخل تحديثين. عند الفشل يتراجع التحديث كاملًا. خذ نسخة PostgreSQL قابلة للاستعادة قبل تحديث قاعدة فعلية. حساب الترحيل يحتاج صلاحية تعديل البنية؛ لا تشغله استجابة لزيارة المستخدم.

فتح الصفحات يتحقق من الإصدار فقط، ويتوقف برسالة تحديث إذا لم يكتمل. لا ينشئ جداول أو يحذف آليات التدقيق. إصدار أقدم من التطبيق لا يقبل قاعدة أحدث.

العمل اليومي: أضف الأقسام، واضبط الرسوم، ثم سجّل الطلاب وما دفعوه والمصروفات. ملف ZIP في القائمة تصدير جميع جداول البيانات مع فهرس وتحقق، وليس نسخة PostgreSQL جاهزة للاستعادة. معاينة GitHub Pages مستقلة عن قاعدة التطبيق.

## حساب المدير والعاملين

الدراسة التفصيلية وحدود المجالات موجودة في [دراسة الحسابات والصلاحيات](docs/ADMIN_ACCESS_STUDY_AR.md).
بعد الترحيل إلى الإصدار 15، أنشئ المدير الأول **مرة واحدة في خطوة التشغيل**:

```sh
python -m access_control bootstrap
```

يقرأ الأمر اسم المدير وكلمة مروره من `[auth]` في `.streamlit/secrets.toml`؛ لا تُمرر كلمة المرور في سطر الأوامر. اسم المستخدم 3–64 حرفًا إنجليزيًا أو رقمًا مع السماح بـ `._-`، وكلمة المرور 12–128 حرفًا. عدّل إعداد المدير القديم إذا كانت كلمته قصيرة قبل الأمر. يرفض الأمر إنشاء مدير ثانٍ إذا كانت الحسابات مهيأة؛ بقية الحسابات من «لوحة المدير». الدخول بعد ذلك من قاعدة البيانات، ولا يُقبل حساب Secrets كمدخل بديل يتجاوز الصلاحيات.

المدير ينشئ اسم العامل واسم المستخدم وكلمة المرور وصلاحيات المجالات. العامل يدخل باسم المستخدم وكلمة المرور، وتظهر له أعماله المسموحة فقط. الإضافة والعرض منفصلان للطلاب والمصروفات؛ التعديل والإلغاء يضيفان العرض. تسجيل الدفعات والرواتب يتيح عرض الحساب اللازم للعمل. المصروفات التشغيلية لا تكشف قيود الرواتب الآلية. التقارير المالية وسجل التغييرات الكامل إذنان صريحان مستقلان. إدارة الحسابات والتصدير الكامل للمدير فقط. كلمة المرور لا تُسترجع؛ تُعاد تهيئتها.

تغيير الحساب أو صلاحياته أو كلمة المرور ينهي جلساته الحالية. انتهاء بالخمول 30 دقيقة وبالعمر 12 ساعة. خمس محاولات دخول خاطئة خلال 15 دقيقة توقف المحاولة على اسم المستخدم 15 دقيقة؛ إعادة تعيين كلمة المرور أو إعادة تفعيل الحساب من المدير تزيل قفل المحاولات. استخدم HTTPS في الاستضافة؛ ربط PostgreSQL وملف الأسرار متاحان للخادم ومسؤول التشغيل فقط. لا تعرّض قاعدة البيانات مباشرة لحسابات العاملين. حسابات العاملين حسابات تطبيق، وليست أدوار PostgreSQL؛ اتصالات الصيانة المباشرة ببيانات اعتماد قاعدة البيانات موثوقة ومستقلة عن الواجهة.

سجل المستخدم ثابت حتى بعد التعطيل، مع منع تعطيل آخر مدير أو إعادة استخدام أسماء المستخدمين. لوحة النشاط تعد الأعمال المحفوظة منذ تفعيل الحسابات، وتعرض الأصل والصافي بعد التصحيح والإلغاء. بيانات الماضي غير المرتبطة بمعرف حساب لا تُنسب تخمينًا إلى عامل جديد. التصدير الكامل يتضمن الجداول الحساسة اللازمة للاستعادة، ومنها بصمات كلمات المرور والجلسات؛ يُحفظ لدى المدير في مكان محمي. نسخة البيانات التي عُرضت أو نُزلت قبل سحب إذن لا يمكن استرجاعها من جهاز العامل.

GitHub Pages يقدم تجربة شكلية محلية للحسابات. الحساب الذي تنشئه هناك لا يمنح دخولًا إلى التطبيق الحقيقي ولا يحفظ شيئًا في PostgreSQL؛ لا تستخدم كلمات مرور حقيقية في المعاينة.

الترحيل 13 يفعّل حماية الصفوف للجداول المعروفة لهذا التطبيق ويسحب منح `PUBLIC` و`anon` و`authenticated` إذا وُجدت. لا توجد سياسات قراءة عامة؛ هذا التطبيق لا يستعمل واجهة REST العمومية للوصول إلى البيانات. اتصال Streamlit الخاص يجب أن يملك جداول التطبيق (كما يحدث عند تشغيل الترحيل بالاتصال نفسه)، ويبقى على الخادم فقط؛ لا تمنحه للعاملين. تُترك الجداول الأخرى في قاعدة مشتركة دون تغيير. يمكن حذف إعداد `[auth]` بعد نجاح تهيئة المدير؛ إعداد PostgreSQL يبقى مطلوبًا.

## صور الطلاب وملفاتهم

الترحيل 13 يضيف student_photos الخاص. الصورة اختيارية عند التسجيل وتُحفظ مع الطفل والأهل والدفعة في المعاملة نفسها؛ يُقبل JPG وPNG وWebP ثابت حتى 5 ميغابايت و12 مليون بكسل، ويعاد ترميزه إلى JPEG بحد أقصى 640 بكسل دون EXIF أو بيانات الموقع. لا تُرفع إلى خدمة خارجية ولا تُنشأ روابط عامة. العرض يحتاج students.view، والتغيير والحذف يحتاجان students.edit. يمكن لمن يملك الإضافة وحدها إرفاق صورة عند التسجيل دون قراءة ملفات الطلاب.

نسخة الصورة مستقلة عن نسخة بيانات الطفل؛ يُرفض الحفظ من محرر صورة قديم ولا يمحو تعديل العنوان صورة أحدث. حذف الصورة يزيل بايتاتها من السجل الحالي ويبقي الملف والحساب؛ سجل التغييرات يحتفظ بالمسؤول والسبب والبصمات والأبعاد فقط، دون الصورة القديمة. قد تحتفظ النسخ الاحتياطية السابقة بصور وقت أخذها. التصدير الكامل يضم الصورة الحالية بترميز base64 في JSON. ملفات الطلاب لا تعرض الحساب المالي أو إجراءاته للعامل دون صلاحيات الدفعات.

معاينة Pages للصور مؤقتة داخل التبويب؛ لا تستخدم صور أطفال حقيقية فيها. الصور في البرنامج الفعلي تُحفظ في PostgreSQL بعد الترحيل.

### التسجيل والديون — ترحيل 14

التسجيل الجديد يعرض «دفع» و«معفي» بحسب الصلاحيات. في الدفع يُختار التسجيل والجيليه افتراضيًا؛ إلغاء الاختيار يلغي فرض ذلك الرسم على هذا التسجيل. الصفر يُحفظ دون وصل، وتبقى الرسوم المحددة دينًا. المبلغ الموجب يحتفظ بالتوزيع السابق ويجب أن يغطي الرسوم المحددة؛ المتبقي للشهور.

تُثبّت أسعار الشهور عند بدايتها، وتستحق الشهرية للتسجيلات الجديدة عند اكتمال الفترة الشهرية من تاريخ البدء، مع معالجة آخر الشهر وفبراير. الحقل due_at_period_end يوحّد هذه القاعدة في الملف والملخص وإلغاء الدين ومعاينة تصحيح الوصل. الحسابات القائمة تبقى على شروطها السابقة، ولا تعاد كتابة الديون أو الوصولات التاريخية. الترحيل ذري ويُشغّل خارج زيارات المستخدم، بالأمر الموضح أعلاه.

كل نماذج التعديل الحالية تفتح داخل نافذة محمية، مع حقول حية وتحذير عند الخروج قبل الحفظ، ثم خيار متابعة التعديل أو تجاهله. النافذة تمنع الإغلاق العرضي؛ زر «إغلاق دون حفظ» هو مسار الخروج في البرنامج الفعلي. صلاحيات الخادم وفحص نسخة السجل تبقيان مرجع الحفظ.

من صفحة الدفعات يمكن تسديد رسوم التسجيل والجيليه المستحقة مباشرة في نافذة قبض مستقلة، دون الدخول في الأرشفة ودون إعادة توزيع الشهرية. التأكيد يفحص المبلغ المعروض والنسخة الحالية داخل المعاملة، وتكرار نفس الطلب لا يضاعف القبض.
